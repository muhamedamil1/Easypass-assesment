Security and data-integrity review:
- No browser Supabase client was created because no real Client Component needs it in Task 01.
- Authenticated server client uses public Supabase env values and Next.js cookies so future user paths preserve JWT/RLS behavior.
- Privileged client is lazy, imports `server-only`, uses only `SUPABASE_SERVICE_ROLE_KEY`, and disables auth persistence, auto-refresh, and URL session detection.
- Public and server env variables are parsed separately; server secrets are only read by the server env module.
- `proxy.ts` refreshes Supabase session cookies and calls `auth.getClaims()`; it is session plumbing only, not an authorization boundary.
- `.env.example` contains placeholders only. `.gitignore` keeps real `.env*` files ignored but allows `.env.example` to be tracked. No migrations, tables, RLS, product UI, seed data, or invoice writes were added.
